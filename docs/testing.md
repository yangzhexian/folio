# Testing Folio

The test suite uses synthetic values and temporary directories. It does not read the user's source documents or open the installed desktop library.

## Automated checks

| Command | What it verifies |
| --- | --- |
| `npm run build` | TypeScript checking and the production frontend bundle |
| `npm test` | Synonym and field-level search, copy formatting and sensitive-field exclusion, independent templates, file-size formatting, sorting, appearance preferences, field insertion/reordering, calendar date arithmetic, and editable attachment names |
| `npm run test:e2e` | Browser interface workflows, appearance, and Tauri event/IPC adapter behavior using public mocks |
| `cargo test --manifest-path src-tauri/Cargo.toml` | SQLite persistence, attachment handling, ZIP validation, and restore recovery using temporary directories |
| `cargo check --manifest-path src-tauri/Cargo.toml` | Rust and Tauri integration compilation |
| `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check` | Rust source formatting |
| `npm run desktop:build` | Windows release executable and NSIS packaging |
| `npm run backend:build` | Console CLI used by the agent data-entry skill |

Install browser support once with `npx playwright install chromium`. Playwright starts the Vite server on `http://127.0.0.1:1420`, or reuses an existing server outside CI. Each test gets an isolated browser context, and browser preview data resets on reload. Failed tests retain a screenshot and trace under `test-results/`; an HTML report is written to `playwright-report/`.

If the browser download is blocked but Google Chrome is already installed, run these PowerShell commands:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'chrome'
npm run test:e2e
```

To inspect a failed trace, run `npx playwright show-trace` with the path printed by the test runner. Test screenshots and reports are ignored by Git and contain only synthetic example data.

They also cover all six sort orders, different creation and modification times after editing, preserved selection when favorites or language changes reorder the list, persisted sorting across filters and reloads, the simplified bilingual toolbar, record creation from an empty library, modal keyboard containment and focus restoration, long-content wrapping, and safe rejection of browser file drops.

Three appearance tests cover light sage defaults, all five accents in both modes, preference persistence, language switching, the quick theme toggle, reset, invalid preference fallback, and selection-ring/swatch centers within half a CSS pixel. Eight native-adapter tests use Tauri's installed public event and IPC mocks to run the actual frontend drop listener: current-record import, duplicate paths, target selection and cancellation, empty-library creation, failure rollback and retry, modal and busy guards, precise file-name search, tooltips, and reload-only retry after a completed import. They also verify unsupported filenames invoke the native open command from both views and rename dialogs edit new suffixes and legacy descriptive names. These mocks do not execute Rust, Windows Explorer, or a default document viewer.

Ten attachment-preview tests pass checked-in synthetic PNG, JPEG, and PDF bytes through the Tauri IPC mock and use real browser image decoding and the PDF.js worker. They cover zoom and fit, pan-ready scrollable content, native file actions, supported-file navigation scoped to the current record or filtered Files results, actual PDF page pixel differences and direct page entry, rapid page/zoom changes, closing/reopening during rendering, stale native reads, object URL cleanup, malformed PDFs, translated size/unavailable/password errors with retries, and absence of remote requests. The compact Chinese dark-mode case checks all controls at 900 × 620, focus containment and restoration. Copy notifications must stay above the preview toolbar. Fixture generation and provenance are documented in `tests/fixtures/README.md`.

Eight field-editor tests cover positional insertion and label focus, aligned insertion buttons, pointer and keyboard reordering, saved field IDs/types/translations/values/sensitivity, drag auto-scroll, Escape cancellation, calendar month/year navigation without changing the field until date selection, invalid manual date validation with unsaved-change protection, compact Chinese calendar layout, and removal of the default student rail destination. Four search tests cover QQ spacing and fullwidth variants, Chinese/English phone and document-number aliases, metadata combined with field queries, matching-field snippets, direct clipboard copying, locating a field on another record, sensitive snippets, and language changes/reload. Browser-preview records reset on reload; save/reopen assertions run in one session, while restart persistence is tested in Rust.

Sorting unit tests include timezone-aware chronology, natural numeric ordering for English and Chinese titles, deterministic ties, malformed dates, input immutability, and validation of saved preferences.

The resource and layout check observes network requests during reload and language switching, rejects external HTTP or HTTPS origins, checks for JavaScript runtime errors, and verifies there is no horizontal page overflow at the minimum 900 × 620 desktop size. It writes English, Chinese, and compact preview screenshots to `artifacts/`. This is a regression check for those observed interactions, rather than an operating-system network audit.

Eight agent-update browser tests exercise external changes through both DOM and native Tauri focus events, selection preservation, deferred refresh while an editor or operation is active, English/Chinese conflict messages, and recovery by discarding and reopening the latest revision. Delayed-load cases confirm that an older read cannot overwrite a completed local mutation and that focus events received during a read are processed afterward.

## Native storage coverage

Rust tests use isolated temporary vaults to exercise record persistence after reopening, attachment import and duplicate names, source preservation, filename sanitization and traversal rejection, batch-import rollback, delete and undo behavior, backup round trips, invalid archive schemas and paths, attachment metadata mismatch, recovery from an interrupted restore, and exclusion of deleted data from exports. Export validation also rejects a synthetic manifest larger than the restore limit. Native drop tests verify managed copies, entire-batch validation before copying, source preservation, and rejection of unsafe Windows paths and directories. Installation-data tests cover copying records, attachments, soft deletions and recovery folders while leaving the legacy database unchanged; existing destination precedence; recovery of a copied restore journal; interrupted migration resumption; rejection of corrupt source data; and actionable location errors. Attachment tests cover single-underscore generated names, replacing the generated suffix, collision rejection, legacy names, and resolving only active managed regular files for opening.

Nine additional preview storage tests cover valid PNG/JPEG/PDF reads, uppercase extensions, deleted attachments and parent records, missing files and directories, unsupported and mismatched formats, byte caps including growth after opening, excessive image dimensions and malformed headers, PDF preambles and camera JPEG trailers, database path traversal, and an actual Windows junction escape. Preview commands return raw bytes only for validated managed IDs and release the store lock before reading the stream.

Ten backend CLI tests cover validation without initialization, duplicate/deleted record IDs, optimistic revisions and managed timestamps, associated read-only record/attachment results, invalid commands and data directories, bounded UTF-8/BOM input, concurrent creation, and a lock that survives vault replacement. Actual separate-process checks also verify structured stdout/stderr and exit codes. An independent agent follows the skill against a synthetic library to create a bilingual contact, import a note, change only the phone, and reject a stale update while preserving other fields and attachments.

## Desktop verification boundary

Browser tests exercise the in-memory preview adapter. They do not prove that Windows native file dialogs, Explorer reveal actions, WebView2 clipboard integration, installer behavior, or installed-app persistence work on every machine. Rust tests exercise the storage layer, while a real desktop smoke test is needed to cover the boundary between the webview and native commands.

Before distributing a build, use a disposable desktop library to create a record, relaunch and confirm persistence, attach two synthetic files with the same basename, verify both originals remain unchanged, copy a path, reveal the managed file, rename it, and verify the extension. Export the library, make a small change, restore the export, and confirm both record data and file bytes are recovered. Check English and Chinese labels, test an offline launch, and retain an independent backup before testing with real personal information.
