# Folio 0.4.2

Folio adds one-click sensitive-field visibility, an independent attachment viewer, and targeted backend edits for agents. English and Simplified Chinese remain supported, and all records, attachment processing, and previews stay on the computer.

## Added

- A record-wide eye button immediately before **Copy record** shows or hides populated sensitive fields. Individual eye buttons remain available, and changing records clears temporary reveals.
- **Settings → Hide sensitive fields** is enabled by default. Turning it off displays values normally in details and search results and removes all visibility buttons. The preference persists across restarts; **Copy record** continues to exclude fields marked sensitive.
- PNG, JPEG, and PDF previews open in a reusable native window. It supports moving, resizing, minimizing, maximizing, and keeping the window on top. The main library remains usable, with attachment switching, zoom/fit, and PDF page navigation available in the viewer.
- Preview language and appearance follow the main window. Attachment revisions refresh renamed, replaced, or removed files without reopening the application. Closing the main window closes its preview.
- `field-update` and `field-delete` modify one field while preserving unrelated record content and field order.
- `attachment-rename`, `attachment-replace`, and `attachment-delete` modify or remove one attachment through the local CLI. The updated `folio-data-entry` skill documents inputs, verification, and conflict recovery.
- GUI attachment dialogs and CLI mutations check the revision they read, so an old rename or removal request cannot overwrite a newer change.

## Data compatibility

Existing libraries and version-1 backups remain readable. Legacy attachments receive a revision token on read without rewriting their stored metadata. New attachment mutations rotate the token; backups omit live tokens and restored attachments receive fresh ones.

Replacing an attachment keeps its ID, parent record, and creation time while publishing a new managed file. The supplied source and previous managed bytes remain unchanged. The response includes `previousPath` for the unreferenced recovery copy; that copy is excluded from normal attachment lists and exports, and its filename stays occupied while the file exists. Attachment removal uses soft deletion. Field deletion has no separate undo command.

## Packages

- `Folio_0.4.2_x64-setup.exe`: Windows installer containing Folio, the backend CLI, agent skill, and license.
- `Folio_0.4.2_x64-portable.zip`: Desktop and CLI binaries with the skill and license. Extract into a writable location and retain the existing adjacent `data` directory when updating.
- `folio-data-entry_0.4.2.zip`: Updated agent skill and CLI reference.
- `SHA256SUMS_0.4.2.txt`: SHA-256 checksums for the three packages.

Close Folio before replacing its executable. Data remains in the existing local library; this version does not encrypt records, files, or backups.
